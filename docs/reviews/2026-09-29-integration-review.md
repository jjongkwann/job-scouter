# 디자인 후속 변경 통합 검토

검토자: `gpt-6-astra`. 구현: 여러 `gpt-6-sol` 에이전트. 기준: [디자인 철학](../design.md), [독립 디자인 감사](2026-09-29-design-expert-audit.md).

## 통합 중 발견해 보완한 문제

- 제안 요약의 Tailwind 스타일이 전역 `.doc` 스타일에 밀려 중첩 카드로 표시되는 문제를 메인이 실제 화면에서 확인했습니다. 요약에 한정한 CSS로 여백·테두리·13px 본문을 적용했습니다.
- 긴 이력서 앞에 옮긴 진행 중 대화 링크에 44px 조작 높이를 적용했습니다.
- 메인의 개발 브라우저에서 후보 상세 복귀 시 검색·정렬 초기화가 발견됐습니다. 저장값 복원 전에 기본 상태를 저장하는 effect가 StrictMode의 두 번째 실행에서 기존 상태를 덮는 원인이었습니다. 저장 effect를 복원 완료 이후로 제한했습니다. 기존 테스트를 StrictMode와 unmount/remount로 강화해 수정 전 실패를 재현했고 수정 후 통과했습니다.
- 인라인 수정 이력이 최근 목록 밖의 `?sha=` 직접 링크를 표시하지 않는 회귀를 보완했습니다. 대상 버전의 diff를 확인한 뒤에만 복원 버튼이 나옵니다.
- 복원 설명은 공통 이력서로 고정하지 않고 실제 `key`의 문서 원본을 표시합니다. 요청 접수와 복원 완료를 구별합니다.
- 미연결 목록의 기존 API 문구는 후보 미존재를 공고 마감으로 단정했습니다. 화면에서는 실제 공고 ID 확인 여부와 현재 후보 연결 여부만 표시합니다.
- 없는 폴더를 지정한 URL에서 API가 기본 폴더를 반환할 때 선택 표시도 실제 응답 폴더와 일치하게 했습니다. 이전 공고의 placeholder는 다른 공고 ID로 이동할 때 재사용하지 않습니다.

## 확인한 경계

운영 `/api/offers`의 보고서 4개에서 첫 문단 전체가 판단·조건을 보존함을 확인했습니다. 필수 차이 표 행이 있는 2개 보고서는 해당 행도 그대로 표시합니다. 점수로 자격 충족을 추정하지 않습니다. 요약 추출은 현재 보고서의 제목 뒤 첫 문단과 `필수요건 차이`/`필수 차이` 행 형식을 사용하며, 다른 형식의 보고서에도 임의의 판단을 만들어 넣지 않습니다.

복원·승인·제외의 요청 실패는 가짜 API로 검증하며 운영 쓰기 동작을 실행하지 않습니다. 실제 브라우저 화면과 배포 검증은 메인이 별도로 수행합니다. 동일 저장소의 변경을 모두 검토했으며 아래 검사를 직접 실행했습니다.


## 감사 항목별 판정

| 항목 | 통합 확인 |
| --- | --- |
| 1. 이력서 작업 진입 | 진행 중 대화·갱신 제안이 DOM과 좁은 화면 모두에서 본문 앞에 위치. 채워진 대화·제안의 격리 테스트 통과 |
| 2. 중요한 제약 노출 | 보고서 첫 문단·필수 차이를 점수 앞에, 파일 제한·확인 사항을 파일 행동 앞에 표시. 원문 전체 유지 |
| 3. 폴더·문서 연속성 | 실제 폴더명으로 구별, URL에 문서 종류 보존, 같은 공고 폴더 로딩 동안 이전 문서를 숨기고 위치 유지. 문서 누락·빈 폴더 안내 및 왕복 테스트 통과 |
| 4. 정보 밀도 | 좁은 데스크톱 초안 목록 2열과 상세 메타데이터 2열 적용. 메인 브라우저 관찰에서 1093px 첫 행 높이 234px → 134px |
| 5. 재탐색 | 후보·초안·파일 상단 검색과 결과 수, 후보 검색 저장/복귀 테스트 통과. 기존 경력 검토·마감 분할 보존 |
| 6. 미연결 문서 | 상세와 목록에서 확인된 ID·후보 연결 상태만 설명. 원문 링크 추가를 일괄 복구 방법으로 안내하지 않음 |
| 7. 읽기 후 복원 | 선택 표시, 인라인 diff, 결과 제목 초점, 선택 버전의 복원 버튼 1개. 최근 목록 밖 직접 링크도 유지 |
| 8. 요청 실패 | 승인·제외·복원 실패를 본문에 지속 표시하고 선택·사유 유지. 접수 불확실성과 실행 후 실패를 구별하는 격리 테스트 통과 |

## 직접 실행한 검사

- `cd web && npm test`: **15개 파일, 34개 테스트 통과**.
- `cd web && npm run lint`: 통과.
- `cd web && npm run typecheck`: 통과.
- `git diff --check`: 통과.
- 후보 StrictMode 복귀 보완 뒤 위 전체 34테스트·lint·typecheck를 다시 실행해 통과했습니다.
- Vite의 향후 `configLoader: native` 기본값 관련 기존 경고가 있습니다. 이번 변경의 오류는 아닙니다.

메인이 수행해 전달한 확인: Python 190개 테스트 통과, 모바일·1093px 실제 화면에서 주요 진입점/문서 전환/검색/복원 diff 초점 확인. 이 결과는 통합 에이전트가 직접 브라우저를 조작한 결과와 구별합니다.

**판정:** 코드 통합과 자동 검사에서 배포를 막는 문제는 남지 않았습니다. 프로덕션 빌드와 최종 화면 확인을 통과한 뒤 배포할 수 있습니다. mini 배포 성공 여부, 배포 리비전·데이터 해시·HTTP 확인 결과는 메인의 배포 검증 기록을 기준으로 합니다. 운영 쓰기 실행, 실물 스마트폰, Safari, VoiceOver, 모든 생성 문서 내용의 정확성은 이번 통합 검토에서 검증하지 않았습니다.
