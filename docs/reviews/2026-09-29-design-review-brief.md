# 독립 디자인 점검 의뢰

요청일: 2026-09-29. 기준 커밋: `a61c5bc`. 사용자의 요청에 따라 구현에 참여하지 않은 새 에이전트를 생성했습니다. 모델은 `gpt-6-astra`, 추론 수준은 `xhigh`입니다. 아래는 실제 위임 프롬프트의 역할·판단 기준·산출물 요구사항입니다.

## 부여한 역할

정보 밀도가 높은 업무용 웹앱을 검토하는 Principal Product Designer / UX Reviewer 역할로 독립 감사합니다. 구현자의 설명이나 테스트 통과를 디자인 품질의 증거로 대신하지 않습니다. 실제 자격을 보유한 사람이라고 주장하지 않습니다.

제품 목적은 ‘근거 확인 → 직접 판단 → 지원 준비’입니다. [디자인 원칙](../design.md)의 우선순위인 정보 정확성, 사용자 통제, 업무 연속성, 탐색·읽기 효율, 시각적 정돈에 따라 판단합니다. Sharer의 내용 우선·조작 크기·상태 표현을 참고하되, 미디어 보관함의 배치를 긴 채용 문서에 그대로 적용하지 않습니다.

## 점검 요청

1. 검토함·후보·지원서류·이력서·자료의 목록과 상세를 실제 운영 화면에서 확인합니다. 공고별 문서 탭과 폴더 선택, 제출용 파일, 보고서, 이력서 하위 화면을 포함합니다.
2. 360·390px 모바일, 1093px 좁은 데스크톱, 1440px 데스크톱에서 대표 화면을 봅니다. 가로 넘침 외에 첫 대상까지의 거리, 반복 정보, 읽기 순서, 다음 행동의 발견 가능성도 평가합니다.
3. 주 메뉴·보조 메뉴·문서 탭의 관계, 상위 목록으로 돌아오기, 제목·설명·통계·도구·목록의 일관성을 검토합니다.
4. 중요한 자격 미충족·감점·응답 기한이 접힘 안에 숨지 않는지, 점수·후보 상태·서류 생성·실제 지원 상태를 혼동시키지 않는지 확인합니다.
5. 글자·간격·색·경계·행동의 우선순위·조작 크기·키보드 의미·로딩·빈 상태·실패·부분 완료를 점검합니다.
6. 문제마다 관찰 증거, 위치, 사용자 영향, 최소 수정안, 완료 기준을 적습니다. 확정 결함·개선 권고·미검증 가설을 구분하며 취향만으로 결함을 만들지 않습니다.

## 범위와 산출물

- 전문가 에이전트가 브라우저 검토를 전담하는 동안 메인 에이전트는 화면 간 연결과 공통 컴포넌트의 소스를 독립 검토합니다.
- 서버 상태를 바꾸는 승인·제외·생성·저장·복원·외부 응답은 실행하지 않습니다. 기존 대화가 없으면 새로 만들지 않고 미검증으로 남깁니다.
- 제품 코드와 운영 배포는 변경하지 않습니다. 점검 문서와 로컬 스크린샷만 작성합니다.
- 핵심 발견은 최대 10개로 정리합니다. P1은 판단·중요 행동 방해, P2는 반복되는 혼란·비효율, P3는 마감 품질입니다. 잘된 점과 화면 커버리지, 다음 수정 순서도 포함합니다.
- 보고서: [전문가 디자인 점검](2026-09-29-design-expert-audit.md). 실제 기기·보조기기와 화면 너비 모의 검사를 구분합니다.

## 메인 에이전트의 교차 검토 범위

운영 API의 읽기 응답과 라우트·공통 컴포넌트·페이지 소스를 대조했습니다. 점검 시점에 후보 236건, 연결된 초안 폴더 283개, 미연결 초안 폴더 21개, 제출용 파일 121세트, 받은 제안 20건, 보고서 37개를 확인했습니다. 진행 중 이력서 대화는 없었습니다.

여러 폴더가 연결된 공고 49개 중 12개는 서로 다른 폴더가 같은 `원본 · 날짜` 라벨로 표시되는 조건입니다. 이력서 보조 행동의 좁은 화면 배치, 목록 검색과 필터 맥락, 접힌 확인 조건, 요청 실패의 토스트 의존도도 확인하고 전문가에게 별도의 재검토 대상으로 전달했습니다. 실행하지 않은 쓰기 동작의 실패 화면은 실제 재현 결과로 간주하지 않습니다.
