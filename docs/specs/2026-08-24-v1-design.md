# job-scouter 설계
> 2026-08-26 사설 디렉터리에서 이전. 개인 인프라 정보(LAN 주소·절대경로·데이터 repo 이름·계정)는 중립 표기로 치환했다. 치환 전 원본은 저장소 밖에 남아 있다.


> 2026-08-24 초안. `job-scout` 스킬(수동 조사)을 durable workflow 위의
> agent 판정 파이프라인으로 승격하는 프로젝트.

## 이름

**job-scout** = 정찰병(수동 조사 스킬, `${DATA_REPO}/.claude/skills/job-scout`).
**job-scouter** = 정찰을 장치로 만든 것 — 대상을 읽어 수치를 즉시 출력하는
측정기. 공고를 읽어 100점 루브릭으로 채점하는 judge activity가 문자 그대로
그 일을 한다. 측정값이 한계를 넘으면 장치가 멈추는 것(토큰 예산 초과 →
미점수 큐 강등)까지 은유가 이어진다.

문서·커밋에서 둘을 항상 구분해 부른다. 한 글자 차이라 섞이기 쉽다.

## 문제 정의 — 무엇이 자동화되고 무엇이 아닌가

현재 사이클(전부 사람+Claude 세션이 수행):

| 단계 | 현재 | 자동화 가능성 |
|---|---|---|
| 공개 API 수집 (원티드·점핏) | `fetch_jobs.py` + launchd 주 1회 | ✅ 이미 무인 |
| 원티드 매칭률·잡플래닛 리뷰 | 로그인된 로컬 크롬 + MCP | ❌ **무인화 불가** — 헤드리스에서 크롬 MCP 접근 불가(실측) |
| 공고 판정 (루브릭 채점) | 세션에서 requirements 원문 읽고 채점 | ✅ **이 프로젝트의 핵심** — agent loop |
| 평판 판정 (리뷰 흐름 해석) | 세션에서 본문 읽고 판정 | ⚠️ 부분 — confidence 낮으면 사람 검토 |
| 마감 갱신·검증·빌드 | `refresh_due.py`, `build.py` | ✅ 이미 스크립트 |
| 등재 확정 | 사람 | ❌ **의도적으로 자동화하지 않음** |

절반은 원리적으로 무인화가 불가능하다(로그인 크롬, 최종 승인). 그래서
아키텍처의 1급 요구사항은 "전자동"이 아니라 **"사람이 끼는 지점에서
멈춰서 기다릴 수 있는 것"** — durable wait + signal이다.

## 엔진 선택: Temporal

| 후보 | 기각 근거 |
|---|---|
| Spark | 오케스트레이터가 아니라 데이터 처리 엔진. 140건 판정은 빅데이터가 아님 |
| Argo Workflows | K8s 전제. 대상 서버(M1 8GB 맥서버)에 K8s가 없고 올릴 이유도 없음 |
| Airflow | 그래프를 미리 선언하는 배치용. 몇 턴 돌지 모르는 agent loop와 "사람 개입 대기"가 부자연스러움(Sensor 폴링뿐). 비교 스케치: `${DATA_REPO}/jobfeed/airflow_dag.py` |
| Prefect | 동적 파이썬 플로우라 차점. durable 대기·signal이 1급 개념인 쪽은 Temporal |
| **Temporal (채택)** | signal 대기가 수동 단계를 정확히 모델링. 재시도·task queue 자격증명 격리. **이미 돌아가는 데모(`jobfeed/temporal_flow.py`, 2026-08-24 전 구간 COMPLETED)와 specwatch 운영 전례** — 학습 비용 0 |

## 아키텍처

```
JobScoutCycle (workflow — 서버, 자격증명 없음)
 ├─ fetch          [io 큐]   공개 API 수집 → 신규 공고 목록
 ├─ judge × N      [llm 큐]  공고당 agent loop 1개 = activity 1개
 │     in:  requirements 300자 캡 + RAG 검색 결과 (k=20)
 │     out: {점수[스택,도메인,레벨,역할,감점], 사유, 근거 인용,
 │           confidence, usage}          ← JSON 스키마 강제
 │     캐시키: (공고id, 루브릭버전, 사실베이스 해시)
 ├─ (평판 미보유 회사) ── signal 대기: 수동 브라우저 조사      ← durable
 ├─ (등재 후보 배치) ──── signal 대기: 사람 승인               ← durable
 ├─ refresh → build [io 큐]  결정론적 검증 게이트 (기존 build.py)
 └─ report         [llm 큐]  사이클 요약 + 비용·latency 집계
```

### task queue 3개 = 자격증명 격리 경계

specwatch compose에서 검증된 패턴을 그대로 쓴다:

| 큐 | 자격증명 | 역할 |
|---|---|---|
| workflow | **없음** | 결정론적 오케스트레이션만 |
| io | 없음 (공개 API) | fetch·refresh·build 서브프로세스, ES 인덱싱 |
| llm | ANTHROPIC 키 **여기만** | judge·report. `activities_per_second` 레이트리밋 |

큐는 라우팅이 아니라 **자격증명 격리 + 유형별 스로틀 경계**다.
(이력서의 "LLM 자격증명이 특정 워커에만 주입되는지를 테스트로 강제"와 동일 축.)

## 설계 판단 기록 — 채택안과 기각안

| 축 | 채택 | 기각한 대안 | 근거 |
|---|---|---|---|
| agent loop 경계 | 공고 1건 판정 = activity 1개 (loop는 activity 안에서 완결) | LLM 호출 1번 = activity 1번 | 대화 상태를 workflow 직렬화에 태우면 이력이 폭발하고 세션 상태가 직렬화 문제가 됨. 판정은 싸고 멱등 — **재시도 = 통째 재실행**이 더 단순 |
| 폭주 방지 | max_turns·max_tokens를 activity 파라미터로, 레이트리밋은 큐 레벨 | 프롬프트로 지시 | 폭주는 지시가 아니라 **타입·설정으로** 막는다(on-the-record에서 확인). specwatch `SPECWATCH_*_MAX_TURNS`·`activities_per_second`가 전례 |
| RAG 인프라 | 서버의 **기존 ES**(PKB)에 인덱스 추가: ①사실베이스 ②판정 판례 ③기업평판 캐시. BM25+kNN 하이브리드, **리랭커 off, k=20** | 새 벡터DB + CrossEncoder 리랭커 | PKB 실측(2026-07): 리랭킹 없음 MRR 0.517 > bge-reranker 0.388 > Qwen3-0.6B 0.492. k 50→20으로 지연 2.4배 개선(품질 동일). 측정 없이 컴포넌트를 늘리지 않는다 |
| 판정 캐시 키 | `(공고id, 루브릭버전, 사실베이스 해시)` | 공고id만 | **겪은 사고**: 2026-08-11 K8s 철회로 사실베이스가 바뀌자 스택 35점 31건 중 14건(45%)이 무효가 됐다. 사실베이스가 바뀌면 판정이 자동으로 재실행 대상이 되어야 한다 |
| prompt 관리 | 루브릭(job-scout SKILL.md §5~6) = 프롬프트 템플릿, git 버전. 모든 판정에 버전 스탬프 | 코드 인라인 | build.py가 "루브릭 v3와 v4 판정이 섞인 배치"를 거부할 수 있어야 함 — 현재의 배점 상한 검사와 같은 층 |
| 세션 관리 | 공고별 세션은 activity와 함께 소멸. 사이클 상태(제외 집합·오늘 판정 목록)는 workflow 상태·DB에 구조화 | 긴 세션 하나에 140건 누적 | 컨텍스트가 곧 비용. 시스템 프롬프트(루브릭)는 사이클 내내 불변 → **prompt cache 적중 극대화**. 구조화해서 넣고 구조화해서 받는다 |
| 비용·관측 | activity마다 usage(토큰·모델·latency) 반환 → workflow 합산. **사이클 예산 초과 시 잔여를 미점수 큐로 강등** | OTel 풀스택부터 | Temporal 이력 자체가 activity 단위 trace. "미점수 N건"은 **이미 운영 중인 우아한 강등 경로**(2026-08-24 백로그 140건 실증). LLM 내부 span은 usage 레코드로 시작, 대시보드가 필요해지면 Prometheus(보유 스택) |

## 사람이 남는 두 지점 — 자동화하지 않는 것이 설계

1. **평판 판정의 반어법·반복 신호.** 스킬에 "자동 판정하지 말 것"이 박힌
   이유가 있다 — 2026-08-11 정규식 일괄 적용에서 "데이터 모델링"을 모델
   학습으로 잡는 오탐이 쏟아졌다. agent는 판정하되 `confidence`를 반환하고,
   낮으면 등재 대신 사람 검토 큐로 보낸다.
2. **최종 등재 승인.** agent가 행을 제안하고 사람이 signal로 배치 승인해야
   candidates.json에 커밋된다. on-the-record의 승인 게이트와 같은 구조.

검증은 LLM보다 **아래층에 결정론적으로** 둔다. 실증: 2026-08-24 build.py가
리뷰 0~1건짜리 회사에 `warn` 판정을 매긴 실수 3건을 빌드 시점에 거부했다.
LLM 판정도 같은 게이트를 통과해야 한다.

## 데이터 경계 — 무엇이 들어오고 무엇이 들어오지 않는가

시스템이 읽는 개인 데이터는 **세 가지뿐**이다:

| 데이터 | 용도 | 도달 범위 |
|---|---|---|
| 사실베이스 (`이력서_사실베이스.md`) | 감점 판정 근거 | 서버 ES 인덱스 + judge 프롬프트 발췌 → **Anthropic API** |
| 판정 판례 (candidates.json rows + skipped 사유) | 판정 일관성 | 서버 ES, 프롬프트 발췌 |
| 기업평판 캐시 | 재조사 방지 | 서버 ES (회사 정보 — 개인 정보 아님) |

**들어오지 않는 것**: PKB 코퍼스 전체(공부 노트·개인 문서·Obsidian) —
ES **서버**를 재사용하는 것이지 데이터를 합치는 게 아니다. job-scouter는
자기 인덱스만 만들고 PKB 인덱스를 읽지 않는다. 이력서 원본(JK.md)·
지원서류(`applications/`)·지원 이력 원문도 불필요(제외 집합은 회사명
목록으로 충분).

유출 표면 2개와 규칙:

1. **Anthropic API** — judge 프롬프트에 사실베이스 발췌가 실린다. 현재
   수동 조사 세션과 동일한 노출 범위이며, 범위가 늘어나는 게 아니라 같은
   범위가 자동화되는 것이다. llm 큐 밖의 activity는 API를 호출하지 않는다.
2. **Temporal 이력(서버 SQLite)** — activity 입출력이 남으므로 사실베이스
   발췌의 사본이 하나 더 생긴다. **:7233/:8233은 LAN 밖으로 열지 않는다**
   (`--ip 0.0.0.0`은 LAN 워커용이지 공개용이 아님).

## 배포 구조 (서버 실측 기반, 2026-08-24)

서버 = M1 **8GB**, ES(:9200)·httpd(:8080)·GitHub Actions runner 상주,
운영 패턴은 compose가 아니라 **launchd**(`dev.<user>.*` 5개). :7233·:8233 비어 있음.

→ specwatch식 compose 전체 이식(Postgres+Temporal+UI+Airflow ≈ 2~3GB)은
ES와 메모리 경합. 대신:

1. **서버는 서버, OrbStack 컨테이너로** (2026-08-24 변경 — 원안은 launchd
   네이티브. OrbStack이 이미 서버에 상주 중임이 확인돼 VM 오버헤드가 신규
   비용이 아니고, 컨테이너 격리·`restart: always`를 공짜로 얻는다) —
   `temporalio/temporal` CLI 이미지로 `server start-dev --ip 0.0.0.0
   --db-filename /data/temporal.db`, `~/.temporal` 볼륨 마운트로 **SQLite
   영속**(재시작에도 이력·대기 상태 유지), UI 내장 :8233.
   1인 서버에 Postgres 클러스터가 주는 것(HA·스케일)은 필요 없다.
2. **워커는 자원이 있는 곳에서** — jobfeed 워커는 repo·로그인 크롬이 있는
   작업 머신에서 `<server-ip>:7233` 접속. 작업 머신이 닫히면 워크플로는 서버에서 durable
   대기, 열리면 재개. 프로젝트 추가 = 큐 하나 + 워커 하나, 서버 불변.
3. **Airflow는 DAG가 생길 때** — `airflow standalone` + launchd (~800MB,
   8GB에서 ES와 빠듯). 웹 UI 기본 :8080이 httpd와 충돌 → :8081.
   현재 무인 배치(daily-research 등)는 launchd로 충분하다.
4. **배포 = push→pull** — 서버의 기존 Actions runner 재사용,
   `launchctl kickstart`. CI 신규 제작 없음.
